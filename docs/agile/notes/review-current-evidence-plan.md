## Smallest concrete mechanism

Choose mechanical summary composition rather than validating arbitrary prose.
A pure validated current-evidence view plus the already classified findings
produces the published summary. The deterministic section derives only supported
fields from the current immutable artifacts; the fixed qualitative assessment
sentence derives from the existing event/finding result. Free-form reviewer
summary text cannot be inserted into that deterministic section or trusted by the
publisher as current run evidence. If retained for diagnostic provenance, label it
as untrusted model assessment and keep it outside the published numerical claim
surface. Finding bodies remain model assessment attached to validated changed
lines; this task does not promise arbitrary prose truth in findings.

Do not invent test/receipt aggregates absent from the producer schema. Count
fields not exposed with a reviewed typed source are omitted. Raw deterministic.log
is inspectable evidence and a contradictory regression input; free-form log
scraping does not become count authority. A current artifact's expected/executed/
completion revision facts must be validated against trusted expected-head facts
before any current claim is emitted. Exact actual field spellings are discovered
from the pinned producer during admitted implementation, not invented here.
Unknown/malformed/mismatched authoritative bindings fail closed. Unsupported
optional counts are omitted with an explicit deterministic omission result;
a valid no-count qualitative verdict is allowed when the existing review
admission laws and trusted head binding pass.

Pure shape/claim/composition contracts belong in practical portable `.cljc`,
for example an adjacent `eta-mu.law.review-evidence` and the existing
`eta-mu.domain.review`. JSON/Node/filesystem/provider objects are decoded at the
plugin/publisher adapter. The CJS publisher reuses the same compiled pure contract
at its effect boundary; it must not restate that law in JavaScript. Plan the small
compiled bridge explicitly and test its parity. If the actual build/publisher
integration exceeds the estimate, stop for reviewed breakdown rather than
quietly expanding the story or using a second semantic implementation.
